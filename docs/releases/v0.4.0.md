# rust-mirror-gui 0.4.0: crate retention and Cargo.lock import

Draft: not released yet. Old crate mirrors can now be removed from the app
safely, and a project's Cargo.lock can be imported so that the mirror holds
exactly the crates.io versions it uses.

## Changes

- **Crate retention page.**
  - **Discover** lists the crate mirrors in a workspace folder, with their
    contents and sizes.
  - **Policy:** next sync's previous mirror, keep the newest N, previous
    mirrors to keep, pinned mirrors and the as-of date. **Save policy in
    catalog** writes `[crate-retention]` so the command line uses the same
    policy.
  - **Preview removal** is read-only. It lists every folder as remove (with
    its size) or keep, with each reason it is kept.
  - **Delete** is enabled only after typing `delete N`. rust-mirror previews
    again just before deleting. If anything changed since the preview, it
    refuses and deletes nothing. The log lists each deleted file and the
    total size freed.
- **Cargo.lock import** (on the Crate catalog page).
  - Add one or more lock files by path, or drop them on the window. Each
    becomes a named source; the name is suggested from the project folder.
  - **Preview import** shows a summary before anything is written:
    - pinned versions added, removed and unchanged per source (with a diff
      when a source is imported again);
    - skipped git and local path entries, with line numbers;
    - refused registries and other problems, with line, column and a
      plain-English fix;
    - a warning when the project also needs git or path sources that the
      mirror cannot provide.
  - Lock sources are listed as groups in the catalog. **Remove…** previews
    removing a source; mirrored files are never deleted.
  - **Crate preview:** each row shows which lock sources require that
    version. Yanked versions that a lock file still uses are flagged. The
    filter also matches source names.
- Deletion jobs no longer show the re-check byte count as if it were
  deletion progress.

## Upgrade

```sh
cargo install rust-mirror-gui --version 0.4.0 --locked
```

- Rust 1.95 or newer is still required.
- The built-in engine becomes rust-mirror 0.5.0, pinned by the published
  `Cargo.lock`.
- No new direct dependencies.

## Validation and limits

- **Tests:** CI runs fmt, clippy and tests on Linux and Windows. New tests
  cover:
  - crate retention refusals in the real worker (nothing is deleted);
  - the import-lock and remove-lock command lines, including Windows drive
    paths;
  - source-name rules and name suggestions.
- **Real runs on Linux** against real crate mirrors:
  - crate retention preview with keep reasons;
  - a stale preview refused after a new mirror appeared (nothing deleted);
  - a successful delete of one mirror (211.7 KiB).
- **Known issue (rust-mirror 0.4.0):** after a successful crate prune, the
  pruned run folders keep `plan.json`. The next preview in that folder
  refuses ("paused run previous generation is missing from discovery").
  Nothing is deleted. Reported upstream.
- **Not tested:** Windows and macOS runtime, Remote Desktop and machines
  without a GPU, screen readers.
