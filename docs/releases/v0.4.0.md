# rust-mirror-gui 0.4.0: Cargo.lock import and crate retention

Released 2026-11-13. Administrators can import projects' Cargo.lock files so
the crate mirror holds exactly the crates.io versions those projects build
with. They can also remove old crate mirrors from the app, with a preview and
a typed confirmation. The built-in engine is rust-mirror 0.5.0.

## Changes

- **Cargo.lock import** (Crate catalog page, **Cargo.lock sources**).
  - Add one or more lock files by path, or drop them on the window. Each
    becomes a named source. The name is suggested from the project folder
    and checked with rust-mirror's rules.
  - **Preview import** writes nothing. It shows, per source:
    - pinned versions added, removed and unchanged;
    - skipped git and local path entries, with line numbers;
    - problems, with line, column and a plain-English fix. Packages from
      another registry refuse the whole import, and the registry is shown
      without any credentials from its URL;
    - a warning when the project also needs git or path sources that the
      mirror cannot provide.
  - **Write** saves the sources through rust-mirror. Importing a source again
    under the same name shows it as **replaced**, with the exact versions
    added and removed.
  - Sources are listed as groups (file, format, pinned versions, import
    date, SHA-256). **Remove…** previews removing one. Existing mirrors and
    their files are never deleted.
  - **Crate preview:** "Included because" names every Cargo.lock source
    that needs a version. Yanked versions that a lock file still uses are
    flagged "yanked, kept for a Cargo.lock". The filter matches source
    names.
- **Crate retention page.**
  - **Discover** lists the crate mirrors in a workspace folder, with their
    contents and sizes.
  - **Policy:** next sync's previous mirror, keep the newest N, previous
    mirrors to keep, pinned mirrors and the as-of date. **Save policy in
    catalog** writes `[crate-retention]` so the command line uses the same
    policy.
  - **Preview removal** is read-only. Every folder is listed as remove (with
    its size) or keep, with each keep reason, including the catalog crates
    and Cargo.lock sources whose versions a kept mirror holds.
  - **Delete** is enabled only after typing `delete N`. rust-mirror previews
    again just before deleting. If anything changed since the preview, it
    refuses and deletes nothing. The log lists each deleted file and the
    total size freed. You can prune the same folder again later.
- Deletion jobs no longer show the re-check byte count as if it were
  deletion progress.

## Upgrade

```sh
cargo install rust-mirror-gui --version 0.4.0 --locked
```

- Rust 1.95 or newer is still required.
- The built-in engine is now
  [rust-mirror 0.5.0](https://crates.io/crates/rust-mirror/0.5.0), pinned by the
  published `Cargo.lock`.
- Crate mirrors that rust-mirror 0.5.0 writes use a newer format (inventory
  schema 5), which older versions of the app cannot read. Mirrors made with
  0.3.0 still work.
- Toolchain mirroring, crate mirroring, network settings and saved form
  values are otherwise unchanged. No new direct dependencies.

## Validation and limits

Evidence is in the
[validation record](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/evals/2026-11-13-v0.4.0-validation.md).

- **Tests:** CI runs fmt, clippy and tests on Linux and Windows: 22 unit
  tests and 17 process tests. New tests cover:
  - crate retention refusals in the real worker (nothing is deleted);
  - an offline Cargo.lock import preview;
  - a credential-free alternate-registry refusal;
  - the import-lock and remove-lock command lines;
  - source names.
- **Real runs on Linux** against crates.io:
  - Cargo.lock import:
    - three real projects, including git and path dependencies and a real
      yanked version (`memchr 2.3.1`);
    - an alternate-registry refusal;
    - a re-import diff and a removal preview.
  - Preview rows with sources, and the download.
  - `cargo fetch --locked` then `cargo build --locked --offline` of two of
    those projects, from the mirror served by a local HTTPS test server.
    The lock files were unchanged afterwards.
  - Crate retention:
    - Cargo.lock keep reasons;
    - a stale preview refused;
    - deleting twice in one folder.
- **Not tested:**
  - Windows and macOS runtime;
  - Remote Desktop and machines without a GPU;
  - screen readers;
  - a real Nexus server;
  - lock formats 1–3 in the app (covered by rust-mirror's own tests).
- **Not in 0.4.0:**
  - mirroring git, path or alternate-registry crates. They are skipped or
    refused, and the offline machine needs git and path sources separately;
  - authenticated Cargo readers.
