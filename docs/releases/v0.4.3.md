# rust-mirror-gui 0.4.3: prebuilt downloads, window opens on older GPU-less Linux

Released 2026-11-15. A patch release. On some Linux machines without a GPU,
for example Ubuntu 20.04, the window did not open. That is fixed, and this is
the first release with ready-to-run downloads for Windows, Linux and macOS.

## Changes

- **Fixed: the window did not open on some Linux machines without a GPU.**
  With an older Mesa software driver (lavapipe on Ubuntu 20.04, for example
  a VM used over Remote Desktop), the app stopped at start with
  "WGPU error: Limit 'max_color_attachments' value 8 is better than allowed
  2". The graphics library asked for wgpu's default limits, which that
  driver doesn't offer. The app now lowers each requested limit to what the
  driver offers, using wgpu's own `Limits::or_worse_values_from`, but never
  below what egui needs (wgpu's WebGL2 limits, with one colour attachment
  and 2048-pixel textures). If a driver offers less than that, the app
  names each limit that is short and suggests another backend
  (`WGPU_BACKEND=gl` or `vulkan`). Machines with a GPU request the same as
  before.
- **Prebuilt downloads**, for the first time. Each GitHub Release from 0.4.3
  on has:

  | System | File |
  | --- | --- |
  | Windows x86-64 | `rust-mirror-gui-0.4.3-x86_64-pc-windows-msvc.zip` |
  | Linux x86-64, glibc 2.28 or newer | `rust-mirror-gui-0.4.3-x86_64-unknown-linux-gnu.tar.gz` |
  | macOS Apple silicon | `rust-mirror-gui-0.4.3-aarch64-apple-darwin.tar.gz` |
  | macOS Intel | `rust-mirror-gui-0.4.3-x86_64-apple-darwin.tar.gz` |

  plus `SHA256SUMS`. Each archive holds one folder with the program,
  `LICENSE` and a `README.txt`. The release workflow builds them from the
  tagged commit with `--locked`, tests them, and attests each file with
  GitHub build provenance.
  - **Windows:** the C runtime is linked in, so no Visual C++
    Redistributable is needed.
  - **Linux:** built on AlmaLinux 8, so it runs on glibc 2.28 or newer:
    RHEL, AlmaLinux or Rocky Linux 8, Ubuntu 20.04, Debian 10, SLES 15 SP4
    or newer. It is not a static (musl) build, because the window loads the
    system's X11, Wayland and graphics libraries.
  - **macOS:** macOS 11 or newer.

## Upgrade

Download the archive for your system from the
[GitHub Release](https://github.com/rustcommons/rust-mirror-gui/releases/tag/v0.4.3),
or:

```sh
cargo install rust-mirror-gui --version 0.4.3 --locked
```

- **The downloads are not code-signed.** Check the archive first:
  - compare its SHA-256 with `SHA256SUMS` (`Get-FileHash` on Windows,
    `sha256sum -c --ignore-missing SHA256SUMS` on Linux,
    `shasum -a 256 -c --ignore-missing SHA256SUMS` on macOS);
  - optionally, check its provenance with
    `gh attestation verify <archive> --repo rustcommons/rust-mirror-gui`.

  Then:
  - **Windows:** SmartScreen may say "Windows protected your PC". Choose
    "More info", then "Run anyway".
  - **macOS:** Gatekeeper may say the developer cannot be verified.
    Right-click the program and choose Open, or run
    `xattr -d com.apple.quarantine ./rust-mirror-gui` once.
- **Linux without a desktop or GPU:** install the window's runtime
  libraries and a font, as listed in the README and in the archive's
  `README.txt` (one `apt` and one `dnf` line). Without fontconfig and a font
  such as DejaVu, symbols like ✔ show as empty boxes.
- Rust 1.95 or newer is still required to build from source. The built-in
  engine is still rust-mirror 0.5.1. Catalogs, mirrors and settings are
  unchanged.
- No new dependencies.

## Validation and limits

Evidence is in the
[0.4.3 validation record](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/evals/2026-11-15-v0.4.3-validation.md).

- **Release workflow dry run** of this release's source, on all four
  targets: build, `--worker --version`, packaging and `SHA256SUMS`.
  - **Windows:** the window was launched and captured with PrintWindow. The
    executable imports no Visual C++ or UCRT runtime DLL.
  - **Linux:** the highest `GLIBC_` symbol version is 2.28. The packaged
    archive started its window under Xvfb, with the default renderer, on
    AlmaLinux 8 (glibc 2.28) and on Ubuntu 20.04 (glibc 2.31) without a GPU.
    On Ubuntu 20.04 (lavapipe, LLVM 12) the app lowered four limits:
    `max_color_attachments` 8 to 2, `max_storage_buffers_per_shader_stage`
    8 to 3, `max_storage_textures_per_shader_stage` 4 to 3, and
    `max_dynamic_storage_buffers_per_pipeline_layout` 4 to 3.
- **Tests:** new unit tests cover lowering the limits, an adapter that
  offers more, the egui minimum, and the error that names each short limit.
- **Not tested:** macOS runtime beyond `--worker --version` (no window
  test); Linux on real old hardware (containers on GitHub runners only);
  RHEL 8 itself and SLES (AlmaLinux 8 has the same glibc as RHEL 8); screen
  readers.
- **Known limits:** unchanged from
  [0.4.2](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/releases/v0.4.2.md#validation-and-limits),
  including the CPU use of Windows' software renderer on some processors.
