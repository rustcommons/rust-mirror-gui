# rust-mirror-gui 0.5.3: upload, download and incremental mirror fixes

Released 2026-11-22. This patch release embeds rust-mirror 0.6.1 and is the
GUI's first release through the complete phase 2 pipeline.

## Changes

- **Publish:** slow uploads no longer fail merely because the server took
  time to reply after storing a file.
- **Crate downloads:** no longer save progress to disk after every chunk,
  which slowed fast downloads.
- **Incremental crate generations:** upstream index backfills no longer
  block extending an existing mirror when immutable crate identities are
  unchanged. The crate preview shows metadata warnings, naming the crate,
  version and changed fields. The crate file is unchanged; the new mirror
  serves the updated index entry. Older mirrors' bytes stay unchanged.
- **Retention:** toolchain Resume and Force work after a prune instead of
  refusing the workspace.
- **Release pipeline:** build, package, audit, sign, publish and verify the
  crate and binaries in one pipeline. Only owner approval permits the
  crates.io publication. The GitHub Release is created as a draft and
  published after its files have been checked. Provenance and SBOM use the
  unified `actions/attest` action without changing the signer workflow or
  verification policy.
- **Least-privilege hardening:** packaging and comparison precede token
  creation; only the publish command receives the token. SBOM generation
  runs separately from checksum collection, fork PRs skip the signing-capable
  build, and only the highest published version is marked latest.
- **Locked dependency maintenance:** `url` 2.5.9 fixes RUSTSEC-2026-0592;
  its required `form_urlencoded` version is 1.2.3. No new dependency is added.

The source for these notes is the dated
[CHANGELOG entry](https://github.com/rustcommons/rust-mirror-gui/blob/main/CHANGELOG.md).

## Upgrade

Download your platform's archive from the
[GitHub Release](https://github.com/rustcommons/rust-mirror-gui/releases/tag/v0.5.3),
or install with Rust 1.95 or newer:

```sh
cargo install rust-mirror-gui --version 0.5.3 --locked
```

No separate engine installation is needed. Catalogs, settings and event
protocol 1 remain compatible. The engine update is additive.

The release has eight assets: the `.crate`, four platform archives, the
CycloneDX SBOM, `SHA256SUMS` and the signed `.intoto.jsonl` bundle. The one
`SHA256SUMS` has six entries: the crate, four archives and SBOM. The bundle
signs those six files and `SHA256SUMS`; it is not itself listed there.

For strict verification, use the command in each archive's `README.txt`:
its signer is `build-binaries.yml`, its signer and source digests are the
release commit, and it refuses self-hosted runners. See the
[verification guide](https://github.com/rustcommons/rust-mirror-gui/blob/main/README.md#download-a-prebuilt-binary).

## Validation and limits

The [validation record](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/evals/2026-11-22-v0.5.3-validation.md)
distinguishes completed local checks from pending release CI. The release
PR must have a green exact-head Trusted publishing dry run: all four targets,
the packaged crate, Windows capture, fontless AlmaLinux 8 and Ubuntu 20.04
launches, and the six-entry checksum file. Its annotations must contain no
deprecation warning. A dry run skips signing and publication; live attestation,
registry and release checks happen after owner approval, with a publication
record afterwards documenting each phase 2 job's first real run.

Known limits are unchanged: screen readers, the macOS window and Wayland
are untested; software rendering can use about 66% of one core on AMD EPYC
during downloads; the binaries are not code-signed. See
[0.5.0's limits](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/releases/v0.5.0.md#validation-and-limits).
