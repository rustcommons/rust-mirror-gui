# rust-mirror-gui 0.5.2: rust-mirror 0.6.0, signed provenance bundle

Released 2026-11-21. A patch release. The app works as in 0.5.1. It
builds in rust-mirror 0.6.0, and its downloads now come with a signed
provenance bundle that you can verify offline.

## Changes

- **Built on rust-mirror 0.6.0.** The engine code, the command line and
  event protocol 1 are the same as in 0.5.4. 0.6.0 updates locked
  dependencies:
  - sha2 0.10.9 → 0.11.1 (with digest, block-buffer, crypto-common and
    cpufeatures);
  - toml 0.8.23 → 1.2.2 (with serde_spanned and toml_parser; toml_writer
    replaces toml_write);
  - hybrid-array and const-oid replace generic-array.

  The TLS stack is unchanged: rustls 0.23.46 and rustls-webpki 0.103.17.
  0.6.0's one breaking change is for library users: `Error::report` now
  holds a toml 1.x value. The app only reads that field, so its source is
  unchanged.
- **Signed provenance bundle:** the release has a new file,
  `rust-mirror-gui-0.5.2.intoto.jsonl`. It holds the Sigstore-signed SLSA
  build provenance for the four archives, the SBOM and `SHA256SUMS`, one
  bundle per line (the same design as rust-mirror 0.6.0). Before uploading
  it, the release checks that:
  - it covers exactly the release files;
  - it verifies offline;
  - it is the attestation GitHub stores.

  It is not listed in `SHA256SUMS`, because it signs `SHA256SUMS` itself.
- **Fuzzing:** four cargo-fuzz targets cover the input the app doesn't
  control:
  - worker event lines;
  - the whole event stream, with its line-size limit;
  - the settings file;
  - company CA files.

  ClusterFuzzLite runs them on pull requests and weekly. See
  [FUZZING.md](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/FUZZING.md).
- **Repository hardening:**
  - no download is piped into an interpreter;
  - the download check runs an archive only after its SHA-256 matched the
    attested `SHA256SUMS`;
  - CI uses Node 24 actions, explicit runner images (`ubuntu-24.04`,
    `windows-2025`), and prints the Rust version in every job.

## Upgrade

Download the archive for your system from the
[GitHub Release](https://github.com/rustcommons/rust-mirror-gui/releases/tag/v0.5.2),
or:

```sh
cargo install rust-mirror-gui --version 0.5.2 --locked
```

**Check a download:**
- compare it with `SHA256SUMS`;
- verify its provenance online:

  ```sh
  gh attestation verify rust-mirror-gui-0.5.2-<target>.<zip|tar.gz> \
    --repo rustcommons/rust-mirror-gui \
    --signer-workflow rustcommons/rust-mirror-gui/.github/workflows/build-binaries.yml
  ```

- or verify it offline, with the bundle next to the archive: add
  `--bundle rust-mirror-gui-0.5.2.intoto.jsonl` (the README has the full
  command);
- add `--predicate-type https://cyclonedx.org/bom` (online) to check the
  archive's SBOM attestation.

Notes:
- **Not code-signed:** Windows SmartScreen and macOS Gatekeeper still ask
  before the first run; the README says what to do.
- **Earlier releases** have no `.intoto.jsonl` file. Their attestations are
  still in GitHub's store, so online verification works.
- **Nothing else changes:** platforms, runtime packages, catalogs, mirrors
  and settings are as in 0.5.1. Rust 1.95 or newer is still required to
  build from source.
- **Dependencies:** no new crate dependencies. Only rust-mirror and the
  locked versions above change.

## Validation and limits

Evidence is in the
[0.5.2 validation record](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/evals/2026-11-21-v0.5.2-validation.md).

- **Release-workflow dry run** of this release's exact source, on all four
  targets: build, `--worker --version` (engine 0.6.0, protocol 1),
  packaging, SBOM and `SHA256SUMS`.
  - **Windows:** the window was captured with PrintWindow.
  - **Linux:** the window was launched in AlmaLinux 8 and Ubuntu 20.04 with
    every system font removed.

  A dry run can't sign. This release's own bundle, attestations and SBOM
  bindings are therefore checked after the tag, on the published files.
- **Reproducibility check** of this release's exact source: two
  independent builds of each target, compared byte for byte.
- **Tests:** unit and integration tests, clippy, cargo-deny, a clean
  package audit, and the fuzz targets' build.
- **Known limits:** unchanged from
  [0.5.0](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/releases/v0.5.0.md#validation-and-limits):
  - on AMD EPYC machines without a GPU, the window uses about 66% of one
    core during downloads;
  - screen readers, the macOS window and Wayland are not tested;
  - the downloads are not code-signed;
  - reproducibility is shown on GitHub's pinned runner images, not across
    different toolchains or machines.
