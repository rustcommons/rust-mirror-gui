# rust-mirror-gui 0.1.0: first release of the desktop app for offline Rust mirrors

Released 2026-11-11. This is a first, deliberately small release. It is one
executable that lets administrators choose Rust toolchains, preview the files,
download and verify them with live progress, stop and resume, add the Rustup
installers, and publish the result to Nexus Raw or another static HTTPS host.
It doesn't require memorizing rust-mirror commands.

## Changes

- **One executable with the rust-mirror library compiled in.** No separate
  rust-mirror installation is needed, and the window and engine versions always
  match.
- **Process isolation.** Every operation runs in a hidden worker copy of the same
  program (`rust-mirror-gui --worker …`) that calls the rust-mirror library. The
  worker reports over a JSON-lines event protocol: hello, stage, artifact, bytes,
  heartbeat, result.
- **The window never blocks.** It shows:
  - the live stage, files and bytes;
  - the time since the last event;
  - a stalled-worker warning when heartbeats stop;
  - a separate note when the worker is alive but nothing is progressing.
- **Stop, then end if needed.** Stop asks the worker to stop at its next safe
  point. "End process now" appears while it is stopping or stalled. Sync explains
  what is kept for Resume. Publish explains that partial remote files must not
  be activated.
- **Pages:**
  - Selections: writes a new configuration file.
  - Plan preview: metadata only, nothing written.
  - Sync: new run, resume or start over.
  - Rustup finish.
  - Publish: optional CA bundle; Basic credentials are passed only to the worker
    and never stored.
- Each page shows the equivalent `rust-mirror` command for scripting.

## Upgrade

This is a new application. There is nothing to migrate.

```sh
cargo install rust-mirror-gui --version 0.1.0 --locked
```

- Rust 1.95 or newer is required to build.
- The engine is the rust-mirror library version pinned in the published
  `Cargo.lock`.
- On Linux the app needs a Vulkan or OpenGL driver and xkbcommon at runtime. See
  the [README](https://github.com/rustcommons/rust-mirror-gui/blob/v0.1.0/README.md#install).
- Configuration files are ordinary rust-mirror schema-1 files, and the generated
  mirrors are ordinary rust-mirror output, usable with the CLI.

## Validation and limits

Evidence is in the
[validation record](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/evals/2026-11-11-v0.1.0-validation.md).

- **Tests:** CI runs fmt, clippy and tests on Linux and Windows. That covers 14
  unit tests and 10 process tests: a scripted fake worker for stall, crash, stop,
  kill and malformed output, plus the real built-in worker.
- **Real runs on Linux** (software rendering, no GPU), against
  static.rust-lang.org:
  - plan preview;
  - a 4-host sync that was stopped and then resumed to completion (about 1.3 GB);
  - Rustup finish;
  - publish to a **local HTTPS test server**, not Nexus.
- **Not verified:**
  - Windows over Remote Desktop, or without a GPU.
  - Any screen reader. Only the Linux accessibility tree was inspected.
  - Offline start on Windows or macOS. On Linux, startup was traced and opens no
    network connections.
  - Interactive use on Windows and macOS.
  - Publishing to a real Nexus server.
- **Not included yet:**
  - A generations and retention page.
  - Loading an existing configuration into the editor.
  - Download sizes before download.
- The plan preview and a later sync resolve metadata separately, so a moving
  channel can change in between.
