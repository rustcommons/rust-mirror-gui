# rust-mirror-gui 0.2.0: works on a corporate network

Release 0.2.0 lets administrators build mirrors from behind a company proxy and
HTTPS inspection, and see download sizes and time left. It builds in rust-mirror
0.3.0.

## Changes

- **Network settings page.** Stored per computer in the app's settings folder,
  never in the shared mirror configuration.
  - Connection: direct, proxy from environment (`HTTPS_PROXY`/`ALL_PROXY` and
    `NO_PROXY`, shown before use), or a manual HTTP proxy URL with an optional
    Basic username and password.
  - A NO_PROXY list and connect/read timeouts.
  - An extra company CA file (PEM). It is added to the built-in trusted roots,
    never replacing them, and its subject, issuer, expiry and SHA-256
    fingerprint are shown.
  - The proxy password stays in memory only. It is handed to the worker as the
    first stdin line and never appears in arguments, environment, logs,
    settings or the **Same as** command.
- **Test connection.** Runs rust-mirror's `check-network`. It shows DNS,
  connect, proxy login, TLS and a small download as passed, failed or skipped,
  each with a plain-English fix.
  - When HTTPS inspection is detected, it shows "Certificate issued by
    <issuer>" from the certificates actually presented.
  - An explicit flow then adds the company certificate: you choose the PEM,
    review its details and fingerprint, and confirm. Nothing is trusted
    automatically.
- **Download sizes.** Plan preview and Sync can measure sizes first (opt-in
  HEAD requests). Plan preview then shows a size column and an "about X of Y
  budget" bar. Sync shows percent, speed and time left. All of these are
  marked as estimates; checksums still decide correctness.
- **Release picker.** In Selections, toolchains can be picked from
  rust-mirror's release list (stable versions with dates, recent beta and
  nightly builds). The list is cached locally, works offline and can be
  refreshed. Typing a toolchain still works.
- **Fix:** the first-run release-list load no longer reports a failure when
  there is no cache yet.
- **Documentation:** the tutorial has a new Corporate network section with
  real screenshots, and the README is updated.

## Upgrade

```sh
cargo install rust-mirror-gui --version 0.2.0 --locked
```

- Rust 1.95 or newer is still required.
- The built-in engine is now rust-mirror 0.3.0 from crates.io, pinned by the
  published `Cargo.lock`. No separate rust-mirror installation is needed.
- Existing mirror configurations, outputs and saved form values keep working.
  Network settings default to **Direct**, which behaves like 0.1.0.
- Publishing keeps its 0.1.0 behavior: its own CA and login fields, and no
  proxy.
- No new direct dependencies in rust-mirror-gui. Certificate parsing and trust
  happen inside rust-mirror 0.3.0, which adds the owner-approved `webpki-roots`
  and `x509-parser`.

## Validation and limits

Evidence is in the
[validation record](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/evals/2026-11-12-v0.2.0-validation.md).

- **Tests:** CI runs fmt, clippy and tests on Linux and Windows: 17 unit tests
  and 14 process tests. They cover:
  - password delivery over stdin, never in arguments;
  - a TLS failure that carries the presented certificate;
  - offline release lists that use no network flags;
  - real-worker certificate inspection.
- **Real runs on Linux** (software rendering), from the GUI and the worker,
  against static.rust-lang.org through a local test proxy that required a
  Basic login and could inspect HTTPS with a test company certificate:
  - connection test failing at TLS ("Certificate issued by CN=Test CA"), then
    passing after the certificate was added;
  - wrong password refused at the proxy-login step;
  - release list refresh (4,445 entries) and offline cache reuse;
  - plan preview with size estimates (about 1.5 GiB for 4 hosts);
  - a sync with percent, speed and time left.
- **Not tested:**
  - real corporate proxies other than that test proxy;
  - Windows and macOS runtime;
  - Remote Desktop and machines without a GPU;
  - screen readers.
- **Not supported:** SOCKS proxies, and proxy logins other than Basic (for
  example NTLM or Kerberos).
