# rust-mirror-gui 0.3.0: crate mirroring

Released 2026-11-13. Administrators can now mirror an organization-approved
set of crates.io crates, with everything they depend on, so that Cargo on the
offline network builds from the mirror. The built-in engine is rust-mirror
0.4.0.

## Changes

- **Crate catalog page.**
  - Load and save the catalog through rust-mirror. The app edits the
    library's JSON form and never writes TOML itself. Saving produces
    canonical TOML: comments and entry order are not kept, and the app warns
    before saving.
  - **Paste from Cargo.toml:** paste a `[dependencies]` block. Each refused
    line shows its line, column and a plain-English fix (git, path,
    `workspace = true`, other registries, or a whole manifest). Usable entries
    are added only after confirmation.
  - **Per-crate rules:** version requirement, features, default features,
    newest N versions, pinned versions, and aliases (two ranges of one crate).
  - Platforms, mirror/download/largest-file limits, publish address, contact
    and parallel downloads.
- **Crate preview & sync page.**
  - **Preview** writes rust-mirror's frozen plan into a new folder. Nothing
    large is downloaded. It shows:
    - one row per crate version, with size (or "unknown"), the yanked,
      lock-only and kept-from-previous flags, and why it is included;
    - a change summary against the previous mirror;
    - the index-read time, with a warning after a day;
    - the library's budget flags (approval is disabled while a limit is
      exceeded).
  - **Why?** shows every path from the catalog to a version, with
    requirements and features.
  - **One approval** for the complete saved preview. Changing the catalog
    needs a new preview.
  - **Download** shows files-verified progress, the current files, Stop and
    **Resume download** (same approved preview), and typed retry-wait reasons
    (rate limited, server unavailable, connection failed).
  - **Client setup** shows the exact `.cargo/config.toml` source-replacement
    snippet for a finished mirror, with the Windows and Unix file locations.
- **Generations** lists crate mirrors with crate and version counts.
- **Publish** accepts crate mirrors. A Base URL different from the catalog's
  publish address is refused before any upload.
- Crate downloads use the existing **Network settings**: proxy, company
  certificate and timeouts.

## Upgrade

```sh
cargo install rust-mirror-gui --version 0.3.0 --locked
```

- Rust 1.95 or newer is still required.
- The built-in engine is now
  [rust-mirror 0.4.0](https://crates.io/crates/rust-mirror/0.4.0), pinned by the
  published `Cargo.lock`.
- Toolchain mirroring, network settings and saved form values are unchanged.
- No new direct dependencies. Crate resolution, verification and catalog TOML
  all happen in rust-mirror.

## Validation and limits

Evidence is in the
[validation record](https://github.com/rustcommons/rust-mirror-gui/blob/main/docs/evals/2026-11-13-v0.3.0-validation.md).

- **Tests:** CI runs fmt, clippy and tests on Linux and Windows: 19 unit tests
  and 15 process tests. New tests cover:
  - crate events, including completion signalled explicitly per file rather
    than inferred from the next file, and retry messages;
  - crate sync preview and approval arguments;
  - real-worker catalog save, load and paste refusals.
- **Real runs on Linux** (software rendering) against crates.io:
  - a catalog built by pasting, with a rule and saved through the library;
  - a preview of 8 crates / 12 versions (about 1.2 MiB) with "Why?";
  - an approved download;
  - a 181-version catalog stopped mid-download at 160/181 and resumed, with
    20.3 MiB reused and 8.9 MiB downloaded;
  - Client setup;
  - generations listing;
  - publish to a **local HTTPS test server** (not Nexus), plus the refusal of
    a mismatched base URL;
  - a real Cargo project using the Client setup snippet: `cargo fetch --locked`
    from the published mirror, then `cargo build --locked --offline`.
- **Not tested:**
  - a real retry wait from crates.io (covered by an automated test only);
  - Windows and macOS runtime;
  - Remote Desktop and machines without a GPU;
  - screen readers;
  - publishing crates to a real Nexus server.
- **Not in 0.3.0:**
  - crate retention in the app (use `rust-mirror crates prune`);
  - opening an existing crate catalog that rust-mirror refuses (fix the file by
    hand);
  - Cargo.lock import;
  - git, path or alternate-registry crates;
  - authenticated Cargo readers.
- **Large catalogs:** the preview table shows 400 rows at a time; use the
  filter to find a crate.
