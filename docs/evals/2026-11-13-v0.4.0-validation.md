# rust-mirror-gui 0.4.0 validation record (2026-11-13)

Scope: the Crate retention page and Cargo.lock import, built on
rust-mirror 0.5.0 from crates.io (checksum
`2e91420909f7441f35399e3a50a664d7a347e1b45672d3866d6a350e54f6ac57`, release
merge `2bf44ca`).

- The crate retention page was first built and tested on rust-mirror 0.4.0.
  Screenshots `crates-12` to `crates-14` come from that build; their top bar
  reads "rust-mirror 0.4.0 built in".
- The Cargo.lock import UI was built against the merged contract
  (rust-mirror `docs/LOCK-IMPORT.md`, `e18f6f8`), then wired to crates.io
  0.5.0.
- Every run marked 0.5.0 below used the published crates.io build.

Environment:
- Debian 12 aarch64, Rust and Cargo 1.99.1 (CI also runs Rust 1.95.0 on
  Linux and Windows).
- Xvfb with Mesa lavapipe, no GPU.
- Real network access to crates.io.
- All outputs under `/tmp`, with isolated throwaway `CARGO_HOME`s for making
  the lock files and for the client test. No Nexus server.

## Automated

`cargo test --all-features` runs 22 unit tests and 17 process tests. New in
0.4.0:
- Command lines for `crates import-lock` and `remove-lock`. A Windows drive
  path passes through `--lock NAME=PATH` unchanged.
- Source-name rules, using the library's `validate_source_name`, and names
  suggested from the project folder.
- Real worker, crate retention:
  - a preview whose next-previous mirror is missing is refused;
  - a plan the library did not produce is refused;
  - in both cases nothing is deleted.
- Real worker, Cargo.lock import (offline):
  - an import preview is accepted, adds `itoa` and skips the local root
    package, and does not change the catalog file;
  - a lock file whose registry URL embeds a user name and password is
    refused, even with `--write`. The diagnostic is `alternate_registry` at
    line 13, the password appears in neither the log nor the report, and
    the catalog file is unchanged.

**Found and fixed during testing:**
- After a refused delete, the page went blank. The listing is now kept on
  failure.
- After Discover in another folder, "Next sync's previous" still pointed at
  the old folder. Choices outside the new listing are now cleared.
- Delete jobs ended with a partial "known sizes" bar. That bar counted the
  pre-delete re-check bytes and is no longer shown for deletions.
- The "removed" banner stayed after a refreshed Discover. It is now cleared.
- "The file's checksum or import time changed" appeared on newly added
  sources. It is now shown only when a source is re-imported.
- rust-mirror 0.4.0: after a prune, the next prune preview in the same folder
  was refused. Reported upstream and fixed in 0.5.0, as the last real run
  above shows.

## Not covered

- service-b was not built offline: its git dependency must be provisioned
  separately, as the app warns. A build with no git access was not
  attempted.
- Windows and macOS runtime; Remote Desktop and machines without a GPU;
  screen readers.
- A real Nexus server.
- Lock formats 1–3 in the GUI. The library's qualification covers them; the
  GUI only shows the reported format number.
