# rust-mirror-gui 0.1.0 validation record (2026-11-11)

This record covers what was actually run for the first release, and what was not.
It also covers the S1–S3 spike checks from [DESIGN.md](../DESIGN.md#33-recommendation-egui-eframe-conditional-on-a-short-spike),
as far as they were feasible on the release day. The owner's own Windows trial is
recorded separately if and when it happens.

Environment for local runs:

- Debian 12 container, aarch64, Rust 1.99.1.
- Xvfb display `:99`, with Mesa 22.3 lavapipe (software Vulkan) and no GPU.
- Network access to `static.rust-lang.org`.
- All outputs written under `/tmp`. No Rustup or Cargo home was used as output,
  and no Nexus server was contacted.

## Automated tests

`cargo test --all-features` runs 14 unit tests plus 10 process tests (`tests/backend.rs`):

- **Fake worker** (scripted, built only with the `fake-backend` feature):
  - successful run with byte/file accounting;
  - typed failure;
  - crash without a result;
  - graceful stop leading to `cancelled`;
  - stalled worker (no heartbeats) flagged, then killed;
  - heartbeat-only slow stage stays "running";
  - malformed and unknown lines counted, not fatal;
  - version/protocol refusal.
- **Real built-in worker:**
  - `--worker --version` reports the library and protocol versions;
  - a library error (missing configuration) arrives as a `result` event and
    nothing is written.

CI runs fmt, clippy (`-D warnings`) and tests on `ubuntu-latest` and
`windows-latest` with Rust 1.95.0. It also builds the Windows release binary and
smoke-tests `--worker --version` on Windows.

## Manual end-to-end runs (real app, real upstream)

These ran through the GUI and through the worker command line, with the built-in
worker on rust-mirror 0.1.1:

| Flow | Result |
| --- | --- |
| Plan preview, 1.90.0 default + rust-src, 4 hosts | 52 files listed from real metadata; nothing written |
| Sync, 1.90.0 minimal, Linux host | Completed: 14 files, about 342 MB recorded |
| Sync, 1.90.0 default + rust-src, 4 hosts | Stopped from the GUI after about 15 s (`cancelled`), then resumed with "Resume" and completed: 62 files, about 1.3 GB |
| Worker stop via stdin cancel line, then `--resume` | Verified files reused (`Reuse:` lines), run completed |
| Rustup finish on a completed sync | Completed |
| Publish to a local HTTPS Raw stand-in (Python, private test CA via the CA bundle field, Basic auth) | Completed; files uploaded and read back by the library |

The publish target was a local test server, **not Nexus**. Nexus itself is
exercised by rust-mirror's own qualification, not by this GUI release.

## S1–S3 spike checks

| Check | Status | Evidence and gaps |
| --- | --- | --- |
| S1 Remote Desktop / no GPU | **Partly checked** | Linux with no GPU: works with Mesa software Vulkan (lavapipe). With no Vulkan/GL driver at all, the window fails to open (wgpu `CreateSurfaceError`); the README lists the packages. **Windows over RDP, and Windows/macOS without a GPU: not tested.** |
| S2 Screen readers | **Partly checked** | On Linux, the AT-SPI tree (read with Cua Driver) exposes names for navigation items, every labelled text field (name and value), checkboxes, radio buttons and buttons. Roles and checked states were not inspected. **No screen reader (NVDA, Narrator, VoiceOver, Orca) was run.** |
| S3 Offline start | **Checked on Linux only** | `strace -f -e trace=connect,execve` over a 12 s startup shows the window plus the `--worker --version` self-check making only Unix-socket connections (X11, D-Bus, nscd) and no network connections. **Windows/macOS offline start: not tested.** |

## Known limits carried into 0.1.0

- Windows and macOS: CI builds and tests on Windows only. Nobody has run the app
  interactively on Windows or macOS.
- Selections writes new configuration files; it can't load an existing one.
- Download sizes aren't known before downloading. Sync resolves metadata again
  after a preview, so a moving channel can differ.
- The generations and retention page is not included.
